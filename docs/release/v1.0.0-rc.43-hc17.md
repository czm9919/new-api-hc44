## 这一版在做什么

hc16 已经把号池运营能力补齐。hc17 解决一个计费策略问题：**签到等奖励的免费额度，只允许在指定分组消耗**（本站场景：「号池」与「公益模型组」），其余分组只扣付费余额，避免免费奖励被拿去打付费模型。

---

## 一、新功能：免费额度可用分组（`FreeQuotaAllowedGroups`）

### 1.1 行为定义

| 配置 | 行为 |
| --- | --- |
| 留空（默认） | 不限制：所有分组消费都优先扣免费额度（与 hc16 及之前一致） |
| 配置分组白名单 | 白名单内分组：消费仍优先扣免费额度；白名单外分组：**只扣付费余额（quota − free_quota），免费额度一动不动**，付费不足则请求失败 |

配置为逗号分隔的分组名（支持空白修剪），例如：

```text
号池,公益模型组
```

### 1.2 覆盖的计费路径

- **预扣费**（`TryReserveUserQuotaUseFree`）：白名单外分组改用数据库条件更新 `quota - free_quota >= 需扣额度`，只扣总余额不动免费部分，成功后同步缓存增量；付费不足时预扣失败（余额不足错误）。
- **结算补扣**（`BillingSession` 钱包通道 + `PostConsumeQuota`）：沿请求的分组策略执行，不会出现「预扣吃免费、补扣吃付费」的错位。
- **用户余额预检**：白名单外分组按「付费余额」判断可用性——只剩免费额度的用户在这些分组会直接收到余额不足提示。
- 白名单策略**在请求发起时按 `UsingGroup` 判定**，auto 跨分组重试时以最终使用的分组为准（预扣与结算通道各按当次分组取策略）。

### 1.3 配置入口

- **后台界面**：侧边栏「号池」→「号池运营」→ 号池设置 → **免费额度可用分组**（输入框，留空不限制）。
- **API**（与号池设置一起保存）：

```bash
curl -X PUT https://你的域名/api/key-pool/settings \
  -H "Authorization: Bearer <管理员token>" \
  -H "Content-Type: application/json" \
  -d '{
    "default_daily_gift_quota": 500000,
    "user_max_tokens_per_submit": 10,
    "allow_user_contribute": true,
    "auto_bind_models": true,
    "free_quota_allowed_groups": "号池,公益模型组"
  }'
```

- 也可以直接改全局选项：`PUT /api/option/` `{"key":"FreeQuotaAllowedGroups","value":"号池,公益模型组"}`。

> 注意：分组名是 new-api 里「分组 key」（channels/用户分组里配置的那个），不是显示名。异步任务类计费（Midjourney/Suno 回调结算）暂不区分分组，仍走默认策略。

## 二、其他

- 号池设置接口新增 `free_quota_allowed_groups` 字段（GET/PUT 透传）。
- 前端「号池运营 → 号池设置」新增输入框与说明文案。
- 新增模型层测试：白名单解析与命中、付费-only 扣减不动免费部分、付费不足时预扣失败无副作用、useFree 包装路径与旧行为一致。

## 三、升级方式

```bash
docker load -i new-api-image-hc17.tar.gz
# compose 镜像 tag 改为 v1.0.0-rc.43-hc17
docker compose -f docker-compose.prod.yml up -d
```

升级后在「号池运营 → 号池设置」把免费额度可用分组填为 `号池,公益模型组`（以实际分组 key 为准）即可生效。
