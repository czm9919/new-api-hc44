## 概述

hc32 落了覆盖表 UI 后，本批补三件运营真正会用到的事，仍然纯前端增量、
后端零改动、无新 option、无迁移：

1. **缺口提示**：统计没有任何 inbox 渠道的事件，页面顶部黄色横幅列出
   数量与 notify_type 清单——这些事件站内看不到，用户只能靠外部渠道获知，
   运营一眼看到「哪个事件在站内是盲区」
2. **事件搜索**：按名称 / 类型码 / 描述 / 偏好键过滤（前端、大小写不敏感），
   事件多时定位更快；无匹配时显示占位行；过滤不影响拉取次数与刷新按钮
3. **CSV 导出**：把「当前过滤结果」导出为带 BOM 的 UTF-8 CSV
   （`notify-event-catalog-YYYY-MM-DD.csv`），渠道列展开成
   `<channel>_default_enabled` / `<channel>_configurable` 两列，
   方便表格软件透视；单元格统一加引号并按仓库既有约定防公式注入
   （`=+-@\t` 开头且非数字的内容前置单引号）

排障备注（本次新踩的坑）：

1. **镜像名必须放在容器 cmd 参数之前**：部署脚本把 `$newTag` 追加在
   `--port 3000 --log-dir /data/logs` 之后，docker CLI 把 `--port` 解析成
   docker run 的 flag，报「unknown flag」并失败（hc32 的脚本同病，当时是手工
   `docker run` 兜的底）。已修正为 `$runArgs += $newTag` 在前、cmd 在后，重跑通过
2. **Git Bash 里 `docker run` 要带 `MSYS_NO_PATHCONV=1`**：否则 `/data/logs`
   会被 POSIX 路径转换改写成 `/data/D:/yingyong/…/data/logs`，容器启动即
   `mkdir` 失败进入重启循环（PowerShell 无此问题）
