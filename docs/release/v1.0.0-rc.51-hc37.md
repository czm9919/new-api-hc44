# hc37 发版说明（版本串 v1.0.0-rc.51+hc37）

**日期**: 2026-11-18
**基线**: hc36（`v1.0.0-rc.51+hc36`，commit `a6fbc23e`）
**范围**: 大转盘抽奖 + QQ 绑定门禁（抽奖 / 免费模型）+ 配套 AstrBot 插件

## 概述

这一版做的是「把免费福利变成可追溯的福利」：新增每日免费抽奖，同时把
**抽奖**和**免费模型**两个白嫖入口统一挂到「绑定 QQ」这一道门禁上，
绑定动作交给配套的 AstrBot 机器人完成。

三块拼图：

| 块 | 位置 | 作用 |
| --- | --- | --- |
| 大转盘 | `/lottery` 页面 + `/api/user/lottery*` | 每日 N 次免费抽奖，奖品直接进免费额度 |
| QQ 绑定 | `/api/user/qq/bind*` + `users.qq` | 面板发一次性码，机器人凭「谁在发消息」落库 |
| 机器人接入 | `/api/qq/agent/*` + `integrations/astrbot_plugin_newapi_qq` | 独立服务令牌，与用户会话隔离 |

为什么要绑定 QQ：免费额度是站点成本，最容易被打包/多号薅。绑定后每个
额度获取点都能追到具体的人，机器人侧还能做拉群与公告触达——这是免费
模型长期开着的前提。

## 机制说明

### 1. 绑定流程（面板 ↔ 机器人）

```
面板                          用户              AstrBot 机器人              站点
 |-- 生成绑定码(8位/10分钟) -->  |                      |                    |
 |                              |-- /绑定 ABCD2345 -->  |                    |
 |                              |                      |-- POST verify ----> |
 |                              |                      |  (X-QQ-Agent-Token)|-- 校验码 -> 写 users.qq
 |                              |<-- 绑定成功 --------- |<-- user_id/username|
 |<-- 刷新后显示 123****89 -----|                      |                    |
```

- 绑定码去掉了 `0/O/1/I` 等易混字符，长度 8，一次性，重新生成会作废旧码
- 一个 QQ 只能绑一个账号，一个账号只能绑一个 QQ（换绑要先解绑）
- 机器人令牌未配置时，`/api/qq/agent/*` 一律 503（默认关闭，不裸奔）

### 2. 抽奖机制

- 奖池、每日次数、是否要求 QQ 全部走 option，运营在页面底部「抽奖设置」改
- 奖品只有两种：`quota`（进免费额度，与签到同口径）和 `none`（谢谢参与）
- 每日次数用 `(user_id, day_key, spin_index)` 唯一索引兜底：并发抽奖只有
  一个请求能抢到同一个下标，另一个撞唯一索引后重新计数，不会超发
- 中奖额度走 `IncreaseUserFreeQuota`，同时抬升 `quota` 与 `free_quota`，
  保证 `free_quota <= quota` 不变量

### 3. 免费模型门禁

判定口径（任一成立即要求绑定 QQ）：

- token 是号池发放的免费级 key（`SourceChannelId > 0`）
- 模型显式出现在 `FreeQuotaAllowedModels` 白名单里（支持 `gpt-3*` 通配）

刻意**不用** `FreeQuotaUsable` 判定：白名单为空时它返回 true（表示免费额度
对所有模型可用），照它判会把付费模型一起拦下来——这是本批最容易踩的坑，
已用单测钉住（`TestEnsureQQBoundSkipsWhenFreeModelWhitelistEmpty`）。

门禁位置：`controller/relay.go` 中 `GenRelayInfo` 之后、`PrepareRequestBilling`
之前。被拒请求不预扣额度、不消耗上游渠道，返回 403 `access_denied`。

> 注意：选渠道的 distributor 是中间件，跑在 `controller.Relay` 之前。所以
> 拿一个「没有渠道」的模型名去验证门禁，会先看到 503 `model_not_found`，
> 根本走不到门禁——验证时要用渠道里真实存在的模型名。

### 4. 老库 `users.qq` 是 NULL（本批实测踩到并已修）

SQLite 上 `AutoMigrate` 加列只对**之后插入**的行补默认值，历史行的 `qq`
是 `NULL`；而 `User.QQ` 是 `string`，`Select("qq")` 扫到 NULL 会直接报
`converting NULL to string is unsupported`。表现：所有老用户打开抽奖页/绑定卡
都拿到 `success:false` + 这条 Scan 错误（HTTP 仍是 200），抽奖也因此不会返回
403 而是直接报错。

修法三层，缺一不可：

1. `model/qq_bind.go` 新增 `EnsureUserQQBackfilled()`，启动时
   `UPDATE users SET qq = '' WHERE qq IS NULL`（幂等，放 `AutoMigrate` 之后）
2. `GetUserQQ` 改成 `Select("COALESCE(qq, '') AS qq")`，读到 NULL 也不炸
3. `User.QQ` 的 gorm tag 加 `default:''`，新库/新行直接是空串

已用两个单测钉住：`TestGetUserQQToleratesLegacyNullColumn`、
`TestEnsureUserQQBackfilledKeepsBoundValue`。

## 接口

```
# 用户侧（UserAuth）
GET    /api/user/lottery              → 开关/奖池/今日剩余次数/QQ 绑定状态
POST   /api/user/lottery/spin         → 抽一次（403 QQ_BINDING_REQUIRED / 429 LOTTERY_NO_SPINS）
GET    /api/user/lottery/records      → 最近抽奖记录
GET    /api/user/qq/bind              → 绑定状态（脱敏 QQ）
POST   /api/user/qq/bind/code         → 生成一次性绑定码（503 QQ_AGENT_UNAVAILABLE）
DELETE /api/user/qq/bind              → 解绑

# 机器人侧（X-QQ-Agent-Token，与用户会话无关）
GET    /api/qq/agent/ping
POST   /api/qq/agent/verify           {code, qq}
GET    /api/qq/agent/verify?code=&qq=&token=

# 管理端（AdminAuth）
GET/PUT /api/user/lottery/settings      奖池/次数/开关/是否要求 QQ
GET/PUT /api/user/lottery/qq/settings   机器人令牌 + 免费模型门禁开关
```

抽奖响应示例：

```json
{
  "success": true,
  "data": {
    "prize": { "id": "quota-2000", "name": "2000 额度", "type": "quota", "quota": 2000, "weight": 15 },
    "prize_index": 2,
    "quota_awarded": 2000,
    "spins_used": 1,
    "spins_remaining": 0,
    "spin": { "id": 18, "prize_id": "quota-2000", "quota_awarded": 2000, "created_at": 1795007123 }
  }
}
```

## 部署与配置（上线必看）

1. **管理端设置机器人令牌**：面板 →「幸运大转盘」→「抽奖设置」→
   「QQ 机器人接入」→ 填令牌（建议 `openssl rand -hex 24`）→ 保存。
   未填时绑定码接口返回 503，抽奖因未绑定 QQ 而全部 403。
2. **安装 AstrBot 插件**：把 `integrations/astrbot_plugin_newapi_qq/` 整目录
   放进 `data/plugins/`，在 WebUI 填 `api_base`（不带 `/api`）与同一个令牌，
   私聊机器人发 `/绑定 测试` 自检。
3. **确认免费模型白名单**：`FreeQuotaAllowedModels` 为空时「免费模型门禁」
   实际不生效（只拦号池免费 key）。要让某几个模型必须绑定 QQ，就把它们
   写进白名单（如 `gpt-3*,gemini-*`）。

## 升级注意

1. **新增两列 + 两张表**：`users.qq` / `users.qq_bound_at`（AutoMigrate 加列）、
   `qq_bind_codes`、`lottery_spins`。历史行的 `qq` 由启动时的
   `EnsureUserQQBackfilled()` 自动补成空串（幂等，不用手工执行 SQL）；
   未绑定的表现就是「不能用抽奖和免费模型」——这正是门禁的预期行为
2. **不要直接改 sqlite 提权/预置 QQ**：容器的 SQLite 连接会在重启时把旧
   WAL checkpoint 回来，覆盖外部写入。要预置数据请先 `docker stop`，
   改完再 `docker start`
3. **回滚**：换回 hc36 镜像即可；新增表和列保留不影响旧版本运行
4. 升级后访问 `/api/status` 确认 `version` 为 `v1.0.0-rc.51+hc37`，
   侧边栏「个人 → 幸运大转盘」可见
5. **首次上线顺序**：先填机器人令牌 → 再让用户生成绑定码；否则用户只会
   看到「QQ 机器人尚未配置」
6. **机器人令牌改不动就重填**：`PUT /api/user/lottery/qq/settings` 传空
   `agent_token` 表示「保持原值」（防止管理员只看不改时把令牌清空），要换
   令牌必须把新值一起传上来；要彻底撤销只能删 options 里的 `qq_agent_token`
   （按第 2 条的 stop → 改 → start 流程）
7. **升级后管理员自己也要绑**：门禁对所有人一致，包括 `role=100`。运营账号
   建议先给自己绑一个 QQ，再开量
