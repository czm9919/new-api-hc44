## 概述

hc31 落了通知事件覆盖表的后端接口（`GET /api/option/notify_event_catalog`），
管理端「目录页」按计划留到本批配 UI。本批只做这一件事，纯前端增量，
后端零改动、无新 option、无数据库迁移，升级后行为与 hc31 完全一致。

## B213 通知事件覆盖表 · 管理端 UI

| 项 | 内容 | 主要落点 |
| --- | --- | --- |
| B213 | 通知事件 × 渠道 × 默认开关覆盖表（只读） | `web/src/features/system-settings/operations/notify-catalog-section.tsx`、`section-registry.tsx`、`zh.json` / `en.json` |

- 入口：管理端 → 运营设置 → 「通知事件」（`/system-settings/operations/notify-catalog`），
  排在邮件设置之后、后台任务之前
- 三张统计卡：事件总数 / 站内信箱覆盖数 / 外部渠道数
- 矩阵：行 = 通知事件（名称 + 描述 + notify_type），列 = 渠道（按接口返回
  `channels` 顺序），每个单元格给出默认送达状态徽标 + 是否可由用户关闭
- 偏好开关列：展示 `preference_key` 字段名、偏好类型语义（三态布尔 /
  默认关闭 / 渠道选择器）与默认态；站内信箱恒显示「恒开启 · 不可配置」
- 数据通过 `useQuery` 拉取，`staleTime 60s`；加载失败给出重试入口，
  重试成功后恢复矩阵（有单测覆盖两个场景）
- 只读设计：不写任何 option，页面仅用于运营自查「哪些事件会走哪些渠道、
  用户能不能关」

排障备注：

1. `FreeQuotaAllowedModels` 在 options 表里**没有行**（hc31 说明中「注册成功」表述
   不准确）：该 option 走 OptionMap 零值语义，缺行等同空串 = 不限制，首次在
   后台保存后才会落行
2. PowerShell 5.1 执行含中文注释的 UTF-8 无 BOM 脚本会按 GBK 解码，可能吞掉换行
   把语句并到注释里（本次升级脚本第一版就因此失败并已 `docker rm` 掉容器）。
   部署脚本一律保持纯 ASCII，或另存为 UTF-8 with BOM
