## 这一版在做什么

hc12～hc15 已经打通了号池的核心链路（多 key 轮询渠道、贡献密钥、每日额度）。hc16 解决的是"运营能不能真用起来"的最后一公里：

1. **号池渠道自愈迁移**——历史上建坏（BaseURL 带 `/v1`、模型写成 `*`、未标记多密钥）的号池渠道，重启即自动修复；
2. **号池运营后台**——设置、渠道健康度、单 key 启停、验活、Token 搜索与补额度，全部可视化；
3. **页面整合**——删除只有空壳的独立号池页，三个入口合并进侧边栏「号池」页。

## 一、新功能

### 1.1 号池运营页（侧边栏「号池」）

原「Contribute Key」菜单更名为「号池」，页面重构为三个 Tab：

| Tab | 面向 | 内容 |
| --- | --- | --- |
| 我的号池 | 普通用户 | 各供应商每日额度、今日剩余、下次重置时间、自助签发 token |
| 贡献密钥 | 普通用户 | 提交上游 key 换每日额度（原有能力保留） |
| 号池运营 | 管理员 | 见 1.3 |

独立的 `/key-pool` 路由页已删除（该页此前无侧边栏入口、仅一个生成表单，无实际价值）。

### 1.2 号池管理 API（8 个新接口）

```text
GET /api/key-pool/settings              号池设置读取
PUT /api/key-pool/settings              号池设置保存
GET /api/key-pool/overview              总览统计
GET /api/key-pool/channels              号池渠道列表（含健康度）
GET /api/key-pool/channels/:id/keys     渠道密钥明细（逐 key 状态）
PUT /api/key-pool/channels/:id/keys/:index  单把 key 启用/停用
POST /api/key-pool/channels/:id/test    渠道逐 key 验活
GET /api/key-pool/tokens                号池 token 搜索/分页
POST /api/key-pool/tokens/:id/reset-quota   补额度（按当日赠送上限回满）
GET /api/user/key-pool/settings         用户侧自助设置读取
```

可配置项（后台「号池运营」页直接改）：

- `DefaultDailyGiftQuota`：每日赠送额度上限
- `UserMaxTokensPerSubmit`：用户单次自助签发 token 数上限
- `AllowUserContribute`：是否开放自助贡献密钥
- `AutoBindModels`：建渠道时是否自动拉取上游模型列表

### 1.3 号池渠道自愈迁移（`MigrateKeyPoolChannels`）

master 节点启动时（`InitOptionMap` 之后、`InitChannelCache` 之前）自动执行，修复三项历史问题：

| 问题 | 修复 |
| --- | --- |
| BaseURL 带了 `/v1`（导致 `/v1/v1/chat/completions` 404） | 去除 `/v1` 后缀 |
| 模型列表为字面量 `*`（上游不支持通配，报无可用渠道） | 用有效 key 请求上游 `/models`，取真实模型列表（上限 300，兼容 `{"data":[...]}` 与裸数组），失败回退默认模型 |
| 渠道有多把 key 但未标记多密钥（整串 key 被当成一把发出） | 置 `channel_info.is_multi_key=true`、`multi_key_mode=polling` |

迁移**幂等**：即使之后手工改坏，重启会再次自动纠正。关闭后台 `AutoBindModels` 开关后，迁移不再强制拉取模型。

## 二、缺陷修复

1. **贡献密钥渠道 404**：拆分验活地址与渠道地址，渠道 BaseURL 不再携带 `/v1`（商汤验活用 `https://token.sensenova.cn/v1`，渠道地址用 `https://token.sensenova.cn`；NVIDIA 同理）。
2. **Token 额度重置不生效**：`Token.Update()` 白名单不含额度字段，新增 `UpdatePoolQuotaFields()` 定向更新 `remain_quota / free_quota / daily_gift_quota / last_daily_gift_date`。
3. **自动绑定模型开关无效**：关闭后建渠道/迁移不再强制拉取上游模型。
4. **后台设置无处可改**：设置类 Option 此前后端存在、前端零引用，现接入运营页表单。
5. 其他：SQL `key` 保留字、测试中 `common.OptionMap` 未初始化、Go typed-nil 误判、bcrypt shell 转义、前端循环依赖、14 个 oxlint 错误清零。

## 三、升级方式

```bash
# 1. 导入镜像（服务器上执行）
docker load -i new-api-image-hc16.tar.gz

# 2. 修改 compose 中镜像 tag 为 v1.0.0-rc.43-hc16（宝塔/生产模板已同步）
docker compose -f docker-compose.prod.yml up -d

# 3. 观察日志确认迁移执行
docker logs -f new-api | grep -i keypool
```

升级前建议先备份数据库（如 `cp /data/new-api.db /data/new-api.db.bak-$(date +%Y%m%d)`）。

## 四、升级后必做的业务配置

以下三项不是代码缺陷，是上线前需要运营侧完成的配置：

### 4.1 NVIDIA 模型定价（否则调用报 `model_price_error`）

自动拉取的 NVIDIA 上游模型（约 85 个，如 `nvidia/llama-3.1-nemotron-70b-instruct`、`mistralai/...`）默认不在倍率表里。两种处理方式任选：

**方式 A（推荐）：配置模型倍率。** 运营后台 → 运营设置 → 模型倍率，按上游计费标准补充这些模型的倍率；或通过 API 批量写入 `ModelRatio` 选项。

**方式 B：开启自用模式。** 未配置倍率的模型将按默认倍率 37.5 计费放行：

```bash
curl -X PUT https://你的域名/api/option/ \
  -H "Authorization: Bearer <管理员token>" \
  -H "Content-Type: application/json" \
  -d '{"key":"SelfUseModeEnabled","value":"true"}'
```

> 注意：自用模式是全局开关，会影响所有未定价模型的放行策略；对外收费站点建议用方式 A。

### 4.2 对外别名映射（可选）

如需把上游原名（`nvidia/...`、`mistralai/...`）映射成 `gpt-4o` 等通用名，在号池渠道的「模型重定向」（model_mapping）中配置 JSON，例如：

```json
{
  "gpt-4o": "nvidia/llama-3.1-nemotron-70b-instruct",
  "gpt-4o-mini": "mistralai/mistral-small-24b-instruct"
}
```

### 4.3 远端自检

部署完成后在服务器上执行体检脚本，确认历史号池渠道已被启动迁移自愈：

```bash
bash deploy/check-keypool.sh /data/new-api.db
```
