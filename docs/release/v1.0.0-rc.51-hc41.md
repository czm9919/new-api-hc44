# v1.0.0-rc.51 · hc41：一键同步官方定价 + 用户可见的价格榜

两个功能是一件事的两半：管理员一键把官方价拉下来，用户立刻能在 `/rankings`
看到「谁最便宜、比官方便宜多少」。hc39 修的是入口被刷，hc40 修的是签到口径，
hc41 补的是**价格本身的可信度**——用户能自己核对本站价与官方价的差距。

---

## 1. 一键同步官方定价

入口：系统设置 → 模型价格 → 上游价格同步 → 工具栏

```
[官方同步范围 ▾] [✦ 一键同步官方定价] [选择价格源]
```

- **官方同步范围**
  - `只补齐未定价的模型`（默认）：只给本站还没有价格的模型补官方价，
    人工调过的倍率一个都不动。
  - `全部按官方价覆盖`：凡是能对上官方价的模型，一律覆盖。
- 点一次按钮 = 拉官方预设 → 自动全选 → 直接进确认弹窗（逐模型列出
  「当前 → 新值」），确认后才写库。没有「静默改价」路径。
- 官方预设走的是 `controller/ratio_sync.go` 里已有的虚拟渠道
  `官方倍率预设(-100)`，与「上游价格同步」页手动勾选完全同一条链路，
  区别只是自动勾选，因此 `buildPricingChanges` 的版本号/并发保护照旧生效。
- 同步成功后顺手刷新一份「官方参考价快照」，价格榜立刻能显示官方对比列。

### 官方价目表到底是什么

`https://basellm.github.io/llm-metadata/api/newapi/ratio_config-v1-base.json`
现在**只有 `billing_expr` / `billing_mode` 两个字段**（403 个模型），不再给
`model_ratio`。这是 hc41 期间实测确认的结构变化，所以：

| 来源 | 内容 | 用途 |
| --- | --- | --- |
| basellm（官方） | `tier("standard", p * 30 + c * 60)` 这类表达式 | 官方参考价，优先级最高 |
| models.dev | `cost.input/output/cache_read`（USD / 1M） | 官方表达式没覆盖的模型兜底 |

两个来源并行拉取，任一失败仍能用另一个出快照（都失败才报错）。

## 2. 单位换算：三处口径必须一致

排行榜上所有价格都是**美元 / 百万 tokens**，换算来自代码而不是猜：

| 场景 | 公式 | 出处 |
| --- | --- | --- |
| 本站倍率 | `ratio × 1e6 / QuotaPerUnit` | `service/task_billing.go`：`quota = tokens × model_ratio` |
| 官方表达式 | `RunExpr(expr, P=1e6) / 1e6` | `pkg/billingexpr/settle.go`：v1 系数就是「$/1M」，`quota = cost/1e6 × QuotaPerUnit` |
| 按次计费 | `model_price` 直接当美元 / 次 | `model.QuotaType == 1` |

`QuotaPerUnit = 500000` 时系数是 ×2：官方 gpt-4 的 `p * 30` 正好落到
`$30 / 1M`，本地 `model_ratio = 1.25` 正好落到 `$2.5 / 1M`。
表达式用真实计费引擎求值（`billingexpr.RunExpr`），**不用正则抠系数**——
带 `tier()`、`max()`、时段条件的表达式也算得对。

## 3. 用户看到的价格榜

页面：`/rankings` 顶部新增「价格榜」卡片（在 Top Models 之前，
因为它不依赖用量日志，空库也照常出数）。

```
#  模型            供应商   输入价/1M   输出价/1M   官方输入价/1M   对比官方
1  deepseek-chat   DeepSeek  $0.15      $0.6        $0.28          −46.4%
2  gpt-4o-mini     OpenAI    $0.15      $0.6        $0.15           0%
…
```

- 排序：按 token 计费的模型按**本站输入价升序**，按次计费的模型排在后面
  并按「每次价格」升序。
- 「对比官方」= `(本站价 / 官方价 − 1) × 100%`，负数=比官方便宜（绿色），
  正数=比官方贵（红色），0 附近算持平。
- 官方对比两列只在管理员同步过快照后出现；没同步时卡片底部明确写
  「管理员尚未同步官方价」，不做假数据。
- 接口：`GET /api/pricing/leaderboard`，公开只读，与 `/api/pricing`
  共用同一个导航开关（`HeaderNavModuleAuth("pricing")`），并且登记进了
  访问令牌路由表（未声明会被 fail-closed 挡成 403）。

## 6. 已知边界（都是实测踩出来的）

1. **模型名要对得上才比得了价**。官方表用裸名（`gpt-4o`），本站用
   `厂商/模型`（`moonshotai/kimi-k2.6`）。排行榜做了规范化匹配
   （去前缀 + 小写，精确优先），实测本站 85 个模型里对上 7 个；剩下的是
   官方表还没收录的新模型（kimi-k2.6 / minimax-m3.1-flash / gemma-4-31b-it
   这类）。**注意：一键同步写价走的是原有的 diff 引擎，按精确名匹配**，
   所以它只会给真正同名的那几个模型改价——想让更多模型接上官方价，
   得先把本站模型名对齐官方命名。
2. **本站目前的倍率是占位值**。线上 85 个模型的 `model_ratio` 全是 37.5、
   `completion_ratio` 全是 1（new-api 对未知模型的默认值），所以价格榜
   一开始全是 `$75 / 1M`，名次只能按名字排。点一次「全部按官方价覆盖」
   才会变成真实价格——这正是这个功能存在的意义。
3. **models.dev 在境内网络很慢/会握手超时**。实测单次 36s，Go 直连还会
   TLS 超时，所以：客户端 `TLSHandshakeTimeout=30s`、整体预算 90s、失败重试
   3 次、并跟随系统代理（`http.ProxyFromEnvironment`）。容器里没配代理时
   基本只有 basellm 那 403 条能落到快照（线上实测就是
   `sources=['basellm'] counts={'basellm':403}`），功能不残但覆盖变小。
4. **快照不会自动过期**。管理员再点一次「一键同步官方定价」就会刷新；
   价格榜只是展示，不影响计费。
5. **按次计费的模型不参与折扣对比**（没有「每百万 token」口径），
   价格榜里单独列「$X / 次」。
6. **排行榜不管用量**。`/rankings` 原有 Top Models 依赖 `logs` 表，
   空库时是空的；价格榜读的是定价配置，所以永远有数——这也是把它放在
   页面最上面的原因。
