# v1.0.0-rc.43-hc23 发版说明

## 主题:修复扩展设置页无法滚动 + 用户管理余额拆分展示(可由管理员配置)

## 功能变更

### 1. 修复:「扩展设置」页面无法上下滚动

现象:设置项一多,页面被直接裁掉,滚轮/触摸都无法滚动,最后一两屏的设置项根本看不到。

根因是布局链上没有滚动容器:

- `AuthenticatedLayout` 的内容区是 `min-h-0 overflow-hidden`;
- `Main` 组件是 `flex min-h-0 flex-1 flex-col overflow-hidden`;
- 而 `enhanced-settings/index.tsx` 之前直接返回一个裸 `div`(`mx-auto flex w-full max-w-4xl flex-col gap-4 p-4`),自身没有 `overflow-auto`。

父级既然都 `overflow-hidden`,页面自己不接管滚动,内容就只能被裁掉。

修复方式:改用全站统一的 `SectionPageLayout` 骨架,和「号池」「渠道」「模型」等页面一致:

- 标题「扩展设置」与「保存全部设置」按钮进入固定头部(`shrink-0`),滚动时始终可达;
- 内容区使用其自带的 `min-h-0 flex-1 overflow-auto` 容器,卡片列自动获得滚动;
- 内容宽度仍约束在 `max-w-4xl`,大屏观感不变。

### 2. 用户管理列表:可用余额拆成「付费余额 / 免费额度」

`user.quota` 是工作余额总额,其中 `free_quota` 是签到等赠送的免费部分(付费余额 = `quota - free_quota`)。用户侧钱包页在 hc20 已经拆开展示,管理员在「用户管理」列表里却只看到一个合并值,分不清哪部分是充值来的、哪部分是赠送的。

现在余额列按拆分形态展示:

```
付费余额     0.0038
免费额度     0.0010      ← 该用户 free_quota > 0 时才出现
已用         0.0022
```

- 数值口径与钱包页一致:`付费 = quota - free_quota`(quota 为正时不给负数),`免费 = free_quota`;
- **免费额度为 0 的用户不单独占一行**——绝大多数用户没有赠送额度,列表里加一行「免费额度 0」纯属噪音;
- 点开余额弹层始终列全「付费余额 / 免费额度 / 累计已用」,隐藏只是列表层的展示优化;
- 总余额为负(透支)时仍保留负号并标红,不因为拆分而被吞掉;
- 列宽在拆分形态下从 160px 放宽到 200px,放得下两列标签+数值;
- 排序仍然按 `quota`(总额)走服务端排序,语义不变。

### 3. 新增「余额显示」配置(管理员全局生效)

入口:**扩展设置 → 余额显示**(`/enhanced-settings`)。四项配置(可全配):

| 配置 | 说明 |
| --- | --- |
| 拆分显示付费余额与免费额度 | 总开关。关闭后所有位置回到单个「可用余额」合计值 |
| 付费余额 / 免费额度显示名 | 留空用默认文案(随界面语言切换);填了按字面显示,适配「充值余额 / 赠送额度」等不同叫法 |
| 在「用户管理」列表拆分显示 | 列表行高敏感,允许与别处区别对待;关闭后该列表仍显示合计 |
| 隐藏免费额度 | 拆分仍开启,但表格里不再单列免费额度那一行(弹层仍可见) |

配套:

- 「效果预览」按当前草稿实时渲染一行示例,不用保存就能看到最终长什么样;
- 「恢复默认」一键回到出厂配置;
- 独立的「保存余额显示配置」按钮,与页面下方号池设置的「保存全部设置」互不影响;
- 保存后自动失效 status 缓存,无需重启即生效。

实现要点:

- 配置存 option `BalanceDisplaySetting`(JSON),刻意做成一个对象而不是 5 个散落的 option:这几项互相耦合(隐藏免费额度只在拆分开启时有意义),一起读写不会出现「改了一半」的中间态;
- 后端 `common/balance_display.go` 提供默认值、读取与校验(只允许合法 JSON 对象);未配置过时返回默认值,而不是空串;
- 通过 `/api/status` 下发(`BalanceDisplay` 字段),前端 `use-balance-display.ts` 走共享缓存读取,不新增请求;
- 前端解析一律「缺省即默认」,同时容忍字符串布尔值:配置损坏或老版本没这个字段,列表页都不会崩。
