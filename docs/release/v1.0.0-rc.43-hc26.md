# v1.0.0-rc.43+hc26 发版说明

**日期**: 2026-11-02
**提交**: `c335869` fix(hc26): /api/user/self 补回 free_quota 字段——签到成功但免费额度恒显示 0

## 问题

老板反馈两条：

1. 「保存还是不行」
2. 「签到免费额度不增加」

## 排查过程（浏览器实测）

用 Playwright 无头浏览器 + 临时密码走完整用户流程复现（`ui-save-probe.py` / `ui-cards-probe.py` / `ui-checkin-probe.py`）：

### 保存链路：hc25 修复有效，全链路实测通过

| 操作 | 结果 |
| --- | --- |
| 扩展设置 → 自定义 Head「保存 Head 代码」 | PUT `/api/option/` 200，落库，刷新回显 ✅ |
| 扩展设置 → 余额显示「保存余额显示」 | 同上 ✅ |
| 扩展设置 → 导航栏「保存导航」 | 同上 ✅ |
| 扩展设置 →「保存全部设置」 | PUT `/api/key-pool/settings` 200，落库 ✅ |
| 系统设置 → 签到设置保存 | PUT `/api/option/` 200，落库，刷新回显 ✅ |

结论：**hc25 的前端修复本身是好的**。若界面上仍遇到「保存失败/不回显」，最可能是浏览器还跑着旧版 JS 缓存——**Ctrl+F5 强制刷新**即可。

### 签到免费额度：真 Bug，已定位

实测复现：签到成功提示「获得 $0.0314（免费额度）」，DB `users.free_quota` 0→15705 正确，**但个人页「免费额度」卡片仍显示 $0**（总余额倒是正常从 $200 → $200.03）。

**根因**：`controller/user.go` 的 `buildSelfUserData`（`/api/user/self` 的 DTO，同时用于 login/refresh 响应）**漏掉了 `free_quota` 字段**。后端加额度逻辑完全正确，但接口永远不下发，前端 `profile.free_quota ?? 0` 恒为 0。

另发现：排查开始时 DB 里 `checkin_setting.enabled` 根本不存在（= 默认关闭），签到功能此前一直没开启过——这也是「签到没反应」的一部分原因。

## 修复内容

- `controller/user.go`：`buildSelfUserData` 增加 `"free_quota": user.FreeQuota`
- `web/src/features/profile/hooks/use-profile.ts`：`syncAuthUserQuota` 同步 `free_quota` 到 auth store
- `web/src/stores/auth-store.ts`：`AuthUser` 类型补 `free_quota` 字段
- 新增回归测试 `controller/user_self_free_quota_test.go`（DTO 必须携带 free_quota）
