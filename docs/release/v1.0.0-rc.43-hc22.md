# v1.0.0-rc.43-hc22 发版说明

## 主题:导航栏自定义 + 修复签到余额刷新 + 拦截同一上游账号重复贡献

## 功能变更

### 1. 新增「导航栏配置」(管理员全局生效)

入口:**扩展设置 → 导航栏配置**(`/enhanced-settings`)。

- **显示 / 隐藏**:分组与单个菜单项都能关;关掉后所有用户的侧边栏都不再出现该入口(路由仍可直达,仅入口消失);
- **自定义名称**:分组与菜单项都能改显示名,留空则沿用默认(已翻译)标题;
- **自定义顺序**:上移 / 下移调整分组顺序与组内菜单顺序;
- **「恢复默认」**:一键回到出厂顺序与名称。

实现要点:

- 侧边栏导航定义从 `use-sidebar-data.ts` 抽到 `web/src/lib/nav-catalog.ts`,每个分组/菜单项都有稳定 id(`general.keys` 这种),配置以 id 为准,不随文案或路由变化;
- 配置存 option `SidebarNavCustom`(JSON),前端 `use-sidebar-nav-custom.ts` 在渲染侧边栏时叠加;
- 只记录差异:配置里没提到的分组/菜单项按默认顺序追加且保持可见,**升级后新增的菜单不会被老配置悄悄藏掉**;
- 与既有「系统设置 → 维护 → 侧边栏模块」(`SidebarModulesAdmin`)叠加生效(两者取交集);个人仍可在「个人资料 → 侧边栏个人设置」里进一步收窄自己的菜单;
- 新配置通过 `/api/status` 下发,保存后自动失效 status 缓存,刷新即生效。

### 2. 修复:签到成功但页面余额没增加

签到奖励是加在 `user.quota` / `user.free_quota` 上的(后端行为正确,`quota` 与 `free_quota` 同时 +奖励),问题在前端:
签到成功后只刷新了「签到状态」这一个 query,个人资料卡上的「当前余额 / 免费余额」仍是旧值。

- `CheckinCalendarCard` 新增 `onCheckedIn` 回调,签到成功后由个人资料页触发 `refreshProfile()`;
- `useProfile` 拿到新资料后同步写回全局登录态的 `quota`,钱包页 / 数据看板 / 顶部用户卡也不会再显示旧余额。

### 3. 拦截「同一上游账号重复贡献」

同一个上游账号下新建的第二把密钥不会增加上游真实额度,只会把同一账号重复计入号池(容量虚增、历史实现还会按 token 重复发放每日额度)。现在:

- **贡献表单新增必填「上游账号标识」**(账号邮箱 / 用户名),用于判定「同一个账号」;归一化处理大小写与空白,`Zhang@Gmail.com` 与 `zhang@gmail.com` 视为同一账号;
- 提交时在验活**之前**判重,命中直接拦截并给出可操作提示,例如:
  - `上游账号 zhang@gmail.com 已贡献过密钥（nvapi****abcd，贡献者 #7），同一账号只能贡献一次；请改用其他账号的密钥`
  - `密钥 nvapi****abcd 已在号池中（贡献者 #7），同一把密钥不能重复贡献`
- 表单会列出「该供应商下你已贡献的账号与脱敏密钥」,避免重复踩坑;
- 判定依据来自新表 `pool_key_records`(只存密钥 SHA-256 指纹,不落明文),并对历史数据兜底:老 key 没有台账时,用号池渠道里真实的 key 判重;
- 运营侧后台发放(`/api/key-pool/generate`)不强制账号唯一(可能确实需要收同一账号的多把 key),但同样记录台账;
- 新增接口:`GET /api/key-pool/accounts`(运营查看已占用账号)、`GET /api/user/key-pool/accounts`(用户查看自己的贡献)。

## 升级步骤

```bash
docker load -i new-api-v1.0.0-rc.43-hc22.tar
docker compose -f deploy/docker-compose.prod.yml up -d
```

数据库迁移:启动时 AutoMigrate 新增 `pool_key_records` 表(**只新增,不改动既有表**)。

配置变更:新增 option `SidebarNavCustom`(未配置时为默认导航,无需迁移);
用户自助贡献新增「上游账号标识」必填项,历史用户下次贡献时补填即可。
