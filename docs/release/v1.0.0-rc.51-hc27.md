## 概述

把上游 QuantumNous/new-api `v1.0.0-rc.51`（自 rc.43 起 **193 个提交**）融合进 hc 二开基线，
保留 hc16~hc26 全部自定义功能，通过全量 Go 测试与前端构建，升版本 hc27 并发布镜像。

## 上游主要变更（rc.43 → rc.51）

- **插件体系**：新增 provider plugins / request plugins / 社区市场（#8271、#8241、#8313）
- **性能**：MoeForge moejs/moego 升级，请求体按需流式读取（#8311）；修复无 AVX 的
  x86-64 CPU 上 SIGILL 崩溃（#8322）
- **稳定性**：多 Key 渠道 Key 全失效后重新启用可恢复渠道（#433830b）；手动禁用在请求
  失败时保持（ada15c0）；SQLite 默认配置修复（9c2c370）；Redis 跨槽与鉴权缓存完整性
  修复（#8218、#8200）
- **功能**：易支付 RSA 签名（#8291）；HOST 监听地址环境变量（#8269）；HTTP/2 健康检查
  （#8059）；Vertex 每渠道 v1beta1 端点开关、缓存服务账号令牌；DeepSeek 搜索/抓取与
  Responses reasoning 补全；Gemini Argon 字段与 embeddings 计费；2FA 锁定后计数重启；
  模型定价变更审查流程；密码校验与反馈优化
- **前端**：依赖整体升级、渠道插件抽屉布局修复、合规提示文案等

## 融合适配与回归修复（0de337d）

上游两个语义变化需要 hc 侧适配：

1. **`Channel.Update()` 不再写 key**（key 只能经 `UpdateChannelLocked` 变更）：
   `service/keypool.go` 号池合并写回改走 `UpdateChannelLocked`。
2. **优先级重试语义**：上游允许在多 Key 渠道内换 Key 重试，与 hc 智能路由
   `smartRetryExclusion`（排除已用渠道）冲突。修复：
   - 多 Key 渠道仍有可用 Key 时（`HasEnabledKey`）不排除，重试落下一个 Key
   - 单渠道排除后无候选时回退到不含排除的候选集（单渠道同渠道重试，多渠道保持排除）

Windows 测试基建修复：

- `model/main.go`：InitDB/InitLogDB 重入只关闭自开连接池（Windows SQLite 句柄未释放
  导致 unlinkat 失败 / 误关测试外部句柄）
- `controller/access_token_audit_test.go`：审计矩阵改自管临时目录 + 统一关池
- `controller/channel_pin_retry_test.go`：清空分组负载均衡覆盖（hc 默认
  `default=smart` 与上游优先级分层断言冲突）
- `service/channel_affinity_usage_cache_test.go`、`relay/common/override_test.go`：
  Windows 时钟粒度撞 key 修复
- `logger/logger.go` CloseLogFile、`middleware/frontend_static.go` Abort 修复、
  `pkg/jsplugin/routing.go`、`service/vguard.go`、前端 pricing/nav 适配
