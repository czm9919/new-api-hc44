# hc38 发版说明（版本串 v1.0.0-rc.51+hc38）

## 概述

hc37 把「大转盘 + QQ 绑定 + 免费模型门禁」跑通了，但管理端设置只有一块
`<textarea>` 塞 JSON、一个密码框、一个保存按钮：错在哪一行看不出来、权重改了
不知道概率变没变、令牌填错了只会得到一句"failed"。这一批把**管理员的设置机制**
整体重做：

| 问题（hc37） | 现在（hc38） |
| --- | --- |
| 奖池靠手写 JSON，格式错才知道 | 表格编辑：名称/类型/额度/权重/实时概率，缺 id 自动补 |
| 保存时静默截断（超 50 次截成 50、非法行直接丢） | 逐字段 400 + `fields[]`，前端定位到具体行；校验失败**不落库** |
| 权重 0 的奖品存进去却不显示 | 保存时直接拦（权重 1–1000），消灭"存了看不见" |
| 改坏了没法回退 | 一键「恢复默认奖池」（`POST /settings/reset`） |
| 令牌只能"填/留空"，看不到当前是哪枚 | 尾号提示 `••••f0c1` + 已绑定用户数 + 待用绑定码数 |
| 轮换令牌要自己去别处生成再粘贴 | 「生成随机令牌」服务端 64 hex，明文只回一次 + 一键复制 |
| 想撤销令牌只能直接改库 | `DELETE /settings` 显式撤销；「空串=保持原值」不再含糊 |
| 令牌没有格式约束（可以存个带空格/换行的） | 16–128 位可见 ASCII，保存前拦 |

## 管理端接口（变化）

```
GET    /api/user/lottery/settings             读奖池（不变）
PUT    /api/user/lottery/settings             保存：逐字段校验，成功回读；400 + code/fields
POST   /api/user/lottery/settings/reset       新增：恢复默认奖池
GET    /api/user/lottery/qq/settings          读：agent_configured/token_hint/require_for_free
                                              + bound_users / active_bind_codes
PUT    /api/user/lottery/qq/settings          {agent_token?, clear_token?, require_for_free}
DELETE /api/user/lottery/qq/settings          新增：撤销令牌
POST   /api/user/lottery/qq/settings/rotate   新增：生成并启用新令牌（明文只回一次）
```

### 错误响应

```json
HTTP 400
{
  "success": false,
  "code": "LOTTERY_SETTINGS_INVALID",
  "message": "lottery settings are invalid",
  "fields": [
    { "field": "daily_spins", "message": "每日次数需在 0 到 50 之间" },
    { "field": "prizes[0].weight", "message": "权重需在 1 到 1000 之间" }
  ]
}
```

令牌相关用 `QQ_AGENT_TOKEN_INVALID` + `fields[{field:"agent_token", message}]`。

### 校验规则（保存时强制）

| 字段 | 规则 |
| --- | --- |
| `daily_spins` | 0–50 |
| `prizes` | 1–12 条（转盘扇区上限） |
| `prizes[i].name` | 非空，≤ 24 字 |
| `prizes[i].type` | `quota` / `none` |
| `prizes[i].quota` | 0–1,000,000；`quota` 类型必须 > 0 |
| `prizes[i].weight` | 1–1000；合计必须 > 0 |
| `prizes[i].id` | 非空且唯一（前端自动生成 `prize-xxxx`） |
| `agent_token` | 16–128 个可见 ASCII，不含空白 |

读取侧仍是宽容解析（`NormalizeLotteryPrizes`）：脏数据不会让用户端页面白屏，
只是被剥掉。

## 升级注意

1. **管理端接口向后兼容**：老的 `PUT /qq/settings` 只传 `require_for_free` 仍然有效
   （不传 `agent_token` = 不动令牌）；`PUT /lottery/settings` 现在会对非法奖池返回
   400，而 hc37 是静默修正——如果之前存进去过权重为 0 的行，读侧会把它剥掉，
   保存时请按报错修正
2. **令牌轮换会立刻踢掉机器人**：轮换后必须把新明文写进 AstrBot 配置并重载，
   否则机器人侧全部 401
3. **撤销令牌等于关闭机器人接入**：绑定码接口立刻回到 503，抽奖因未绑定而 403
4. 回滚：换回 hc37 镜像即可；新增路由在旧版本不存在，前端会自动回落到旧接口
   （hc37 前端只会调 GET/PUT）
5. 升级后 `/api/status` 应为 `v1.0.0-rc.51+hc38`

### 403 是怎么绕过去的

MCP 的 GitHub 集成走的是 **GitHub App 安装令牌**，权限被限定在已有仓库的 contents 上，
`POST /user/repos` 必然回 `403 Resource not accessible by integration` —— 跟仓库名为空、
参数写错都无关，换个思路才有解：

```bash
# 1) 本机 Git Credential Manager 里存着账号的 OAuth token（scopes: gist, repo, workflow）
printf 'protocol=https\nhost=github.com\n\n' | GCM_INTERACTIVE=never git credential fill
# → username=czm9919  password=gho_…（40 字符，GCM 走 OAuth 设备流拿的，不是 classic PAT）

# 2) 用这枚 token 打 API 建仓库（不需要 gh CLI、不需要浏览器）
curl -X POST https://api.github.com/user/repos \
  -H "Authorization: Bearer $GH_TOK" \
  -d '{"name":"astrbot_plugin_newapi_qq","private":false,"auto_init":false}'

# 3) 推送时 GCM 自动复用同一枚凭据
git push -u origin main --follow-tags
```

`gho_` 这枚 token 带 `repo` scope，而 `repo` 本身就包含建仓权限，所以整条链路一次通了。教训：**MCP 集成没权限不代表
本机没权限**，先 `git credential fill` 看一眼凭据再决定要不要人工介入。

### 插件市场（v1.0.2）

AstrBot 的市场**不是爬 GitHub 的**。读 `astrbot/dashboard/services/plugin_service.py` 可见默认源：

```
plugins  → https://api.soulter.top/astrbot/plugins
md5      → https://api.soulter.top/astrbot/plugins-md5
兜底     → github.com/AstrBotDevs/AstrBot_Plugins_Collection/.../plugin_cache_original.json
```

索引条目由 `cloud.astrbot.app` 的发布流水线生成（带 `download_url` / `commit_sha` / 下载量），
条目 ID 是 `author/name`（`get_market_plugin_id()`，:338-363）。所以推上 GitHub 只是第一步，
没提交就永远不会出现在市场里。

v1.0.2 把「进索引」自己补齐了：

| 文件 | 作用 |
| --- | --- |
| `market/plugins.json` | 一条自定义源索引，ID `czm9919/astrbot_plugin_newapi_qq`，`download_url` 指向 v1.0.2 的 Release 资产 |
| `market/plugins-md5.json` | `{"md5": "..."}`。客户端会把源 URL 的 `.json` 换成 `-md5.json` 去取；取不到就**永远吃旧缓存** |
| `docs/marketplace.md` | 三种「搜不到」的判定、自定义源步骤、官方提交检查表、发版时三件套（版本/下载地址/MD5）维护顺序、排障 |

用户侧操作（无需注册任何账号）：

```
AstrBot WebUI → 插件 → 插件市场 → 右上「源管理」→ 添加源
URL: https://raw.githubusercontent.com/czm9919/astrbot_plugin_newapi_qq/main/market/plugins.json
```

端到端校验（模拟客户端，13/13 通过）：索引 200 且含条目、条目 `author/name` 可拼出 ID、
`md5(索引字节)` 与 `plugins-md5.json` 一致、`download_url` 200、zip 内单一顶层目录
`astrbot_plugin_newapi_qq/`、zip 内 `metadata.yaml` 为 `v1.0.2` / `author: czm9919`。

要进**官方**市场仍需人工一次：<https://cloud.astrbot.app/publish> 提交仓库地址（需 AstrBot
Cloud 账号）。CI 检查项：zip ≤16MB（我们 6.8KB）、`metadata.yaml` 五件套（name/desc/version/
author/repo，齐全）、仓库卫生（`.git`/`__pycache__`/真实配置已排除）。

顺带修的：`verify-plugin-v101.py` 默认路径改成优先取脚本同目录的 `main.py`。之前只认
`integrations/astrbot_plugin_newapi_qq/main.py`，在独立仓里跑 README 那句命令会直接
`FileNotFoundError` —— 也就是说 README 声称的「可复现自检」当时只在主仓成立。
