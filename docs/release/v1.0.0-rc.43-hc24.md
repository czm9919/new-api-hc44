# v1.0.0-rc.43-hc24 发版说明

## 主题:新增「自定义 Head 代码」——解决标签加不进 `<head>` 的问题

## 为什么要做

不少平台（站长验证、搜索引擎收录、统计、第三方客服/挂件）要求把一段 `<meta>` / `<script>` 放在 `</head>` 之前。
后台原本没有对应入口，只能去「系统设置 → 站点 → 首页内容」里填，结果怎么填都不生效。

原因：`HomePageContent` 是渲染在**页面正文区**的 Markdown 内容（`/` 首页那块欢迎文案），
和在 `<head>` 里放标签完全是两件事：

- 它被插进的是 `<body>` 里的 React 容器区域，不是 `<head>`；
- 通过前端渲染写入的 `<meta>` / `<script>` 既不会被搜索引擎当作 head 元信息，`<script>` 也不会执行；
- 上游对统计只支持 `UMAMI_WEBSITE_ID` / `GOOGLE_ANALYTICS_ID` 两个环境变量，且改完要重启进程。

## 功能变更

### 新增「自定义 Head 代码」(管理员全局生效)

入口:**扩展设置 → 自定义 Head 代码**(`/enhanced-settings`)。

- 一个大文本框，原样接收任意 head 片段：`<meta>`、`<script>`、`<link>`、多行多条都支持；
- 服务端在返回 `index.html` 时插到**最后一个 `</head>` 之前**，所以：
  - 对全站所有前台路由生效（`/`、`/users`、`/enhanced-settings` 等 SPA 路径共用同一份 HTML）；
  - 直接访问 `/index.html` 的爬虫/验证工具也能拿到（单独兜了一层）；
- 保存后**刷新前台即可生效**，不需要重启进程；
- 提供「清空」与「打开前台查看」，方便自助验证；
- 保存前做三层校验：
  1. 前端即时校验（超长、误贴整个 `<html>` 文档、自己又写了一遍 `</head>`）；
  2. 后端 `ValidateCustomHeadHTML` 同样规则再挡一次（绕过前端直接调接口也拦得住）；
  3. 注入时找不到 `</head>` 就原样返回，配置写坏也不会白屏。
- 「首页内容」字段下补了一行提示，明确告知这里只渲染正文、要进 head 请去「扩展设置 → 自定义 Head 代码」。

### 顺带修复:hc22 新增的两个接口没登记访问令牌作用域

`TestAccessTokenRouteRulesCoverEveryDashboardRoute` 会校验「每个面板接口都必须在访问令牌规则表里声明且只声明一次」。
hc22 新增的 `GET /api/key-pool/accounts`、`GET /api/user/key-pool/accounts` 漏登记，导致该测试失败、且用访问令牌调用这两个接口时行为未定义。
本次已补进 `middleware/access_token_routes.go`（`accessTokenAnyRule`），路由包测试恢复全绿。

## 使用示例

```html
<meta name="google-site-verification" content="xxxxxxxx" />
<meta name="baidu-site-verification" content="codeva-xxxx" />
<script defer src="https://example.com/widget.js" data-id="123"></script>
```

保存后打开前台，查看网页源代码，这段内容应出现在 `</head>` 上一行。
