# v1.0.0-rc.51 · hc43：前端扁平化 / 极简风

这一版只做一件事：把界面的「圆角 + 投影 + 彩色光晕」换成「1px 描边 + 灰阶层级」。
功能、接口、数据一个没动，改动全部落在 `web/`。

改完的效果：同一个页面，深度关系由**边框**而不是**阴影**表达；颜色只留给数据和
语义（成功/警告/错误），UI 本身是石墨灰阶。品牌色、语义色、图表色都还在，只是
不再作为装饰大面积铺开。

## 1. 三层落地，先令牌、再组件、最后页面

只改令牌就能覆盖 90% 的界面，剩下 10% 是写死在组件 class 里的装饰。

| 层 | 文件 | 改了什么 |
| --- | --- | --- |
| 令牌 | `web/src/styles/theme.css` | `--radius` 1rem → 0.5rem；`--shadow-*` 全部置为透明；默认配色换成灰阶 ink |
| 组件 | `card/badge/button` + `index.css` | 圆角收紧、徽章去胶囊、按下位移删除、卡片 hover 不再浮起、表格去掉逐行入场 |
| 页面 | 首页 / 模型广场 / 公共头 / 看板 | 去掉彩色 radial 光斑、渐变文字、毛玻璃、扫描光效 |

## 2. 令牌层：一个 `--radius` 管全站

```css
/* web/src/styles/theme.css:98 */
:root {
  --radius: 0.5rem;   /* 原来是 1rem */
}
```

`rounded-sm…4xl` 都是 `calc(var(--radius) * n)`（`@theme inline` 里定义），
所以这一个数字就把卡片、弹窗、下拉、输入框、侧栏项一起收紧了，不需要逐组件改。

## 3. 令牌层：阴影整族失效，深度改由描边承担

```css
/* web/src/styles/theme.css:157 */
--shadow-2xs: 0 0 #0000;
--shadow-xs:  0 0 #0000;
--shadow-sm:  0 0 #0000;
--shadow-md:  0 0 #0000;
--shadow-lg:  0 0 #0000;
--shadow-xl:  0 0 #0000;
--shadow-2xl: 0 0 #0000;
```

Tailwind 的 `shadow-*` 工具最终都读这几个变量，所以 `shadow-md` / `shadow-2xl`
写在 300 个组件里也不会再画出投影——**一处归零，全站生效**。

前提是浮层必须自带 1px 边界，否则会「飘」在背景上。逐个确认过：

| 浮层 | 自带边界 |
| --- | --- |
| dialog / popover / dropdown / select / context-menu / hover-card | `ring-1 ring-foreground/10` |
| sheet / drawer / floating-window / chart tooltip | `border` |
| artifact / mockup / sidebar floating | `border` 或 `ring-1` |

没有裸阴影浮层，因此可以直接归零。若将来新增只有 `shadow-2xl` 的浮层，记得补
`ring-1`。

## 4. 令牌层：默认配色改成石墨灰阶

默认主题（`preset: 'default'`）不再用蓝色主色，改成 ink：

```css
/* 亮色：主色=近黑，文字=近白 */
--background: oklch(0.995 0 0);
--primary:    oklch(0.235 0 0);
--border:     oklch(0.905 0 0);

/* 暗色：主色=近白，画布=炭黑，卡片只比画布亮一档 */
--background: oklch(0.165 0 0);
--card:       oklch(0.205 0 0);
--primary:    oklch(0.93 0 0);
--border:     oklch(1 0 0 / 11%);
```

保留颜色的只有：`--success/warning/destructive/info`（语义）、`--chart-1..5`（图表，
饱和度整体下调约 30%）。其余 7 个彩色预设（玫瑰花园、湖光……）原样保留，仍然
可用，只是它们现在也享受「无阴影 + 小圆角」的结构。

顺带把配置抽屉里 `默认` 的色板缩略图从彩虹渐变改成了石墨渐变
（`web/src/components/config-drawer.tsx:284`，`lib/theme-customization.ts:30`），
避免「选默认却看到彩色缩略图」。

## 5. 组件层：四处结构性调整

```css
/* web/src/styles/index.css:561 —— 卡片 hover 只换表面色阶 */
[data-slot='card']:hover { background-color: color-mix(in oklch, var(--foreground) 2%, var(--card)); }
```

| 调整 | 之前 | 之后 |
| --- | --- | --- |
| 卡片 hover | `translateY(-1px)` + `0 4px 12px` | 表面色阶 +2%，无位移 |
| 按钮按下 | `active:translate-y-px` / `scale(0.98)` | 只靠底色变化 |
| 表格行 | 11 档错峰入场动画 | 只保留 hover 底色过渡 |
| 徽章 | 胶囊 `rounded-4xl` | `rounded-md` |

另外把 `.glass-1…5` 五个「玻璃拟态」工具类改成普通卡片表面（`bg-card border`）。
类名保留，因为 `gateway-card.tsx` 还在引用；行为已经扁平。

## 6. 页面层：去掉装饰，保留信息

- **首页 hero**（`features/home/components/sections/hero.tsx`）：删掉三团彩色
  radial 光斑；`bg-gradient-to-r from-blue-400 via-violet-400 to-purple-500` 的
  渐变标题改成「主行 ink + 次行 muted」；顶部徽章从蓝色胶囊改成等宽字灰底 chip，
  去掉 `animate-ping` 呼吸点；应用卡片去掉 `backdrop-blur-xs`、`scale-[1.02]`、
  阴影。
- **模型广场 hero**（`features/pricing/index.tsx`）：同样的三团光斑换成一张
  1px 网格（`bg-[size:4rem_4rem]` + 自上而下淡出遮罩），从导航栏下方开始铺，
  不再压住顶栏。
- **公共头**（`layout/components/public-header.tsx`）：滚动后原本是
  `rounded-2xl + backdrop-blur-2xl + 0 2px 16px 阴影`，现在是 `rounded-lg +
  1px 描边`；移动端整屏菜单去掉 `backdrop-blur-2xl`。
- **终端演示卡**（`hero-terminal-demo.tsx`）：`backdrop-blur-sm` + 20px 投影
  → `bg-card border`；状态点从带光晕的 emerald 改成 `bg-success`。
- **看板设置卡**（`dashboard/components/overview/overview-dashboard.tsx`）：
  删掉顶部来回扫过的高光线（3.2s 无限循环）和 `backdrop-blur`。
- **计费模式徽章**（`pricing/components/model-billing-mode-badge.tsx`）：
  `按量计费` 从 `info` 蓝改成 `neutral` 灰。85 个模型里 84 个都是按量计费，
  它不该是页面上唯一的高饱和色；按次/动态计费仍然用 warning 标出来。

## 8. 已知边界

- **只影响默认主题**：用户如果手动选了其它彩色预设，配色会回到预设自己的色板，
  但圆角、阴影、动效仍然是扁平的（这些是全局的）。
- **深色画布变暗了一档**：`--background` 从 `oklch(0.235)` 降到 `oklch(0.165)`。
  对比度更高，但如果站点里有硬编码 `#1f1f1f` 的自定义块，会比画布亮一档。
- **构建耗时**：`bun run build` 本机约 20 分钟（react-icons 物化 + 2.7 万模块），
  镜像构建改用 `Dockerfile.local-dist` 复用 `web/dist`，只编译 Go。

## 9. 部署

```powershell
# 1. 前端产物（本机）
cd web; bun run build
# 2. 镜像（只编 Go，前端直接拷 web/dist）
docker build -f Dockerfile.local-dist --build-arg APP_VERSION=1.0.0-rc.51+hc43 `
  -t delta-api/new-api:v1.0.0-rc.51-hc43 .
# 3. 换容器（备份库 -> 重建 -> 健康检查），脚本见 deploy-hc43.ps1
```

> `Dockerfile.local-dist` 依赖 `web/dist/index.html`，而 `.dockerignore` 里原本
> 排除了它（防止把本地产物烘进默认镜像）。这版在 `.dockerignore` 末尾加了
> `!web/dist/index.html` 和 `!web/dist/static` 两条白名单，默认 Dockerfile 不受
> 影响（它在第 53 行会先 `rm -rf ./web/dist`）。

## 10. 实测：容器路线受阻，改由计划任务跑本地二进制

部署当天本机 Docker 引擎起不来，容器路线整晚不可用，最终用**同一份代码编成
Windows 二进制**上线，数据目录与容器时代完全相同（`data/` bind mount，同一个
SQLite 文件），所以版本与行为一致。

### 10.1 Docker 侧故障（未解决，留档）

| 现象 | 证据 |
| --- | --- |
| 引擎启动后 30–60s 整体退出 | `com.docker.backend.exe` 与 `Docker Desktop.exe` 同时消失，日志止于 `otelmgr collector starting` |
| 手动起发行版报挂载失败 | `Wsl/Service/CreateInstance/CreateVm/MountDisk/HCS/E_ACCESSDENIED` |
| VM 内看不到数据盘 | `wsl -d docker-desktop -- df -h /` 只有 125.7M 的 initramfs，`/var/lib/docker` 不存在 |

即：`D:\Docker\DockerData\disk\docker_data.vhdx`（65.8 GB）挂载被拒，dockerd 没有
数据盘可起。排除过的原因：磁盘空间（D 盘剩 9.4 GB，数据目录总共 46 MB）、ACL
（SYSTEM/Administrators 均 FullControl）、服务权限（已提权把
`com.docker.service` 拉起并运行成功）。`wsl --shutdown` 后偶发能进 VM 一次，
说明是挂载竞态而非权限缺失，但没有稳定解法。

### 10.2 实际部署方式

```powershell
# 1. 只编译 Go，前端走已构建的 web/dist（embed 进二进制）
go build -trimpath -ldflags "-s -w" -o D:\workbuddy\2026-10-12-19-15-15\new-api-hc43.exe .
# 2. 计划任务托管（onlogon + 立即运行），进程由任务计划程序持有，不随 shell 退出
schtasks /create /tn "new-api-hc43" `
  /tr 'powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "D:\workbuddy\2026-10-12-19-15-15\serve-hc43.ps1"' `
  /sc onlogon /f
schtasks /run /tn "new-api-hc43"
```

`serve-hc43.ps1` 里有两处必要的兼容处理：

- PS 5.1 的 `Start-Process` 遇到 `HTTPS_PROXY` 与 `https_proxy` 同时存在会抛
  `ArgumentException`（字典键冲突），脚本先删小写再启动；
- 前台 `& $app --port 3000 --log-dir data\logs` 让任务计划持有进程，避免
  `Start-Process` 的子进程随宿主 shell 一起被回收（试过一次，命令返回即端口消失）。
