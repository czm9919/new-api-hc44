# hc35 发版说明（版本串 v1.0.0-rc.51+hc35）

**日期**: 2026-11-17
**基线**: hc34（`v1.0.0-rc.51+hc34`，commit `3029a463`）
**范围**: 新增「渠道健康总览」（智能路由健康记忆的运营台出口），共 **1 项功能**

## 概述

智能路由从很早就在维护一套进程内健康记忆：每个渠道 / 每个模型的
成功与失败按半衰期衰减计数、首字延迟 EWMA、失败后冷却。这些信号一直
只喂给路由算法（`model/channel_health.go`），运营台看不到——出了问题
只能翻日志反推「哪个渠道最近老失败」。hc35 把这套记忆以**只读快照**
暴露出来，补上运营侧的可见性（B13–B15）。

口径上的三个决定：

1. **坏渠道置顶**：渠道表按「有样本在前、成功率升序」排（同率按样本数
   降序），无样本渠道垫底按 id 升序——运营打开页面第一眼就是最可疑的
   渠道，而不是一个字典序列表
2. **衰减后的样本数就是「样本数」**：`samples` / `success_rate` 都是半衰期
   衰减后的实时值，不是历史累计；页面直接展示设置里的半衰期 / 冷却 /
   置信阈值，避免拿累计口径误读成功率
3. **「异常渠道」= 样本充足且成功率 < 50%**：`summary.degraded` 用
   `SmartMinSamples` 兜住小样本抖动（只有 2 个样本全失败不算异常），
   与路由算法自己的置信口径一致

## 接口

```
GET /api/channel/health/overview    （ChannelRead 鉴权）
```

无参数。响应结构：

```json
{
  "success": true,
  "data": {
    "channels": [
      {
        "channel_id": 7, "name": "bad-channel", "type": 1, "status": 1,
        "tag": "", "group": "default", "priority": 0, "weight": 0,
        "has_samples": true, "success_rate": 0.12, "samples": 42.5,
        "ttft_ms": 1300.5, "latency_ms": 0, "cooling_down": true,
        "active_count": 2
      }
    ],
    "models": [
      { "group": "default", "model": "gpt-4o", "success_rate": 0.95,
        "samples": 300, "ttft_ms": 450 }
    ],
    "summary": { "total": 3, "with_samples": 2, "cooling_down": 1, "degraded": 1 },
    "settings": {
      "half_life_minutes": 10, "fail_cooldown_seconds": 45,
      "min_samples": 10, "load_penalty": 1
    },
    "generated_at": 1763000100
  }
}
```

`status`：1 启用 / 2 手动禁用 / 3 自动禁用。`cooling_down` 表示该渠道
当前处于 `SmartFailCooldownSeconds` 冷却窗口内，路由不会选它。

## 升级注意

1. **无新增表、无新增 option、无数据迁移**：只读进程内健康记忆与
   `channelsIDM`，`data/` 结构与 hc34 完全一致。hc34/hc35 镜像均未单独
   构建（Docker 阻塞期），线上由 hc33 直接升到 hc36，回滚目标是 hc33
2. **进程重启后记忆冷启动属预期**：健康记忆在内存里，重启后所有渠道
   显示「暂无样本（进程刚启动或该渠道未被调用）」，随真实流量逐步回填；
   不要把空表误判为「没有渠道」或「没有流量」
3. **纯读接口、零副作用**：不写库、不修改路由状态；`ChannelRead` 权限
   （管理员）才可见，未登录 401
4. 本批实际跳版上线：访问 `/api/status` 看到的是 `v1.0.0-rc.51+hc36`
   （hc34 与 hc35 合并在同一镜像里），侧边栏「渠道 → 渠道健康」
   仅管理员可见
