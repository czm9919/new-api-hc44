## 这一版在做什么

三件事：

1. **彻底移除风控中心 / 工单 / 代理分销**——管理后台与引擎整体下线，内容合规继续由既有的违规防护（敏感词 / VGuard）承担；
2. **新增单模型自动检查与自动下架**——巡检逐模型探测，坏模型自动下架、恢复自动上架；
3. **修复管理员菜单对普通用户可见**——`requiredRole` 此前只有声明没有消费点。

## 一、移除风控中心 / 工单 / 代理分销

**后端删除：** `controller/risk_control.go`、`service/risk_engine.go`、`service/risk_control.go`、`service/risk_limit.go`、`middleware/risk_limit.go`、`model/risk_control.go`；`main.go` 的风控引擎定时任务、relay 路由上的 RiskLimit 中间件、`/api/admin/risk/*` 与用户工单/代理/分销公开接口全部摘除。

**前端删除：** 风控中心（概览/规则/事件/封号策略）、工单（管理员+用户侧）、代理申请、分销页面与全部侧边栏入口、路由文件。

**涉及数据表（不再迁移，可手工清理）：** `risk_rules`、`ban_policies`、`risk_events`、`tickets`、`ticket_replies`、`affiliate_config`、`agent_applications`。

```bash
# 可选：升级后清理存量表（sqlite）
sqlite3 /data/new-api.db "DROP TABLE IF EXISTS risk_rules; DROP TABLE IF EXISTS ban_policies; DROP TABLE IF EXISTS risk_events; DROP TABLE IF EXISTS tickets; DROP TABLE IF EXISTS ticket_replies; DROP TABLE IF EXISTS affiliate_config; DROP TABLE IF EXISTS agent_applications;"
```

## 二、单模型自动检查与自动下架

巡检任务（「自动测试渠道」定时任务，`monitor_setting`）新增逐模型模式：

- **开启方式**：后台「号池 → 号池运营 → 号池设置 → 单模型自动检查与自动下架」（选项 `monitor_setting.model_auto_check_enabled`，默认关）。需同时开启「自动测试渠道」。
- **行为**：对渠道每个模型单独发一次测试请求：
  - 上游 **404** 或响应体明确表示「模型不存在 / 未授权」（`model_not_found`、`does not exist`、`not authorized for model` 等关键词）→ **自动下架**该模型（仅禁用该渠道的 ability 行，渠道与其他模型不受影响）；
  - 401 / 429 / 5xx / 超时等瞬态或渠道级错误 **绝不下架**，避免误杀；
  - 之前被下架、本次恢复的模型 **自动重新上架**；
  - 全部模型失败且错误为渠道级（鉴权/欠费）→ 走既有的渠道自动禁用管线。
- **请求数**：等于模型数（NVIDIA 号池 85 个模型时每轮约 85 个请求），按需开启。
- 下架/恢复动作记录在系统日志；巡检汇总新增 `models_delisted` / `models_recovered` 计数。

## 三、管理员菜单对普通用户隐藏

- `requiredRole` 字段此前只声明未消费，普通用户能看到整个管理组菜单（渠道/模型/用户/兑换码/订阅/系统设置等），点进去被路由守卫重定向 403，但入口暴露。
- 现在侧边栏在数据出口统一按当前用户角色过滤：低于所需角色的条目不渲染、空分组收起。
- 管理组普通条目补 `ADMIN` 门槛：渠道、模型、用户、兑换码、订阅；系统信息/任务插件/系统设置保持 `SUPER_ADMIN`。

## 四、顺手修复

- **access_token 路由声明缺口**：hc16 新增的号池 13 条路由、以及 VGuard/实名/订阅自助等 14 条历史路由未在 `accessTokenRouteRules` 声明，新增令牌调用会报 `ACCESS_TOKEN_ROUTE_UNDECLARED`，已全部补齐（`TestAccessTokenRouteRulesCoverEveryDashboardRoute` 由失败转为通过）。
