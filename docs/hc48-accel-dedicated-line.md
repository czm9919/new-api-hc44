# hc48 · 加速专线（付费订阅）

## 这一版解决什么

用户愿意为「不卡」付钱，但原站点没有「通道」这个概念：所有人共用同一批渠道，
上游链路好坏全凭运气。hc48 把「加速通道」变成一个可售卖的分组：

- 管理员配套餐（分组 + 月费 + 并发上限）；
- 用户按月付费解锁该分组；
- 用户把这个分组设到令牌上，请求就走绑了专线出口的渠道。

加速本身不是代码能变出来的：**入站加速（DCDN）与出站专线（代理出口）都要在
基础设施侧配置**，本版只解决「谁有资格用、怎么收费、怎么防滥用」。

## 两层链路

| 段 | 怎么做 | 是否改代码 |
|---|---|---|
| 入站：用户 → 站点 | 独立加速域名接 DCDN / 全站加速，关缓存、开 SSE 不缓冲、源站只放行回源 IP | 否 |
| 出站：站点 → 上游 | 新建一组渠道绑定专线出口（渠道的代理字段填 `socks5://` 或 `http://`），分组设为加速分组 | 否 |
| 售卖与放行 | 套餐订阅、扣费、分组动态放行、并发限制 | **是（本版）** |

备案是国内入站加速的硬门槛；没备案只能先用境外节点，改善有限。出站专线才是
用户真正能感知到的部分，建议先做这一段。

## 数据模型

`accel_plans`（套餐）

| 字段 | 含义 |
|---|---|
| `group_name` | 解锁的分组名，必须与「分组倍率」里的名字一致 |
| `price_per_month` | 月费（额度单位），只从付费余额扣 |
| `concurrency` | 单用户并发上限，0 为不限 |
| `enabled` / `sort_order` | 是否可购买 / 排序 |

`user_accel_subs`（订阅，`user_id` 唯一）

| 字段 | 含义 |
|---|---|
| `group_name` / `price_per_month` | 购买时的分组与价格**快照**：套餐改价或删除都不影响存量订阅 |
| `expire_at` | 到期时间（unix 秒），每次续期顺延 30 天 |
| `auto_renew` | 关闭后到期前仍可用，到期自然失效，不做按天退款 |
| `last_charge_error` | 最近一次续费失败原因，直接展示给用户 |

## 计费口径

- 月费走 `model.TryReserveUserQuotaUseFree(userId, price, false)`，**只扣付费余额**
  （`quota - free_quota`）。用 `DecreaseUserQuota` 会先吃免费额度，等于把赠送额度变现。
- 顺序是「先原子扣费 → 再写订阅」，写库失败会退款并记系统日志（资损必须留痕）。
- 重复开通返回 `409 ACCEL_ALREADY_ACTIVE`，不会重复扣费。
- 续费失败（余额不足）会把订阅置为 `expired` 并写入原因，**不做宽限期**，
  避免出现「已欠费但还在用专线」的账期漏洞。

## 分组放行链路（关键）

`middleware/auth.go` 的 `TokenAuth` 是唯一可信的拦截点：

```
token.Group 非空
  → service.UserCanUseGroup(userId, userGroup, tokenGroup)
      ├─ 静态可用分组命中 → 放行
      └─ 否则查订阅：GroupName 匹配且未过期 → 放行
  → 不通过：受套餐保护的分组回「需要订阅」，其余回「无权限」
```

为什么不能只靠配置：`GetUserUsableGroups()` 是**静态**配置，按用户分组给列表。
把加速分组写进去，所有用户都能白嫖；不写进去，付费用户又永远进不去。
订阅表补的就是「按用户动态放行」这一块。

playground 的 `group` 参数（`middleware/distributor.go`）走同一套判断，
否则网页端传一个 `group` 就能绕过令牌限制。

## 管理端配置步骤

1. **分组倍率**：系统设置 → 分组倍率，加一条 `accel: 1.3`。
   没有倍率的分组会被 `TokenAuth` 判成「已废弃分组」并 403。
2. **用户可用分组**：**不要**把 `accel` 加进去。加了等于对全体用户免费开放，
   前台还能直接看到这个分组。管理端建套餐时会校验并拒绝这种配置。
3. **渠道**：新建一组渠道，分组填 `accel`，代理填专线出口地址。
   这组渠道的模型列表决定加速线路能调哪些模型。
4. **套餐**：侧边栏「加速专线」页 → 套餐管理 → 新建。
5. **`auto` 分组不会纳入加速分组**（`GetUserAutoGroup` 走静态判断），
   用户必须显式指定 `group=accel` 才会走专线，不会被自动路由「偷偷扣钱」。

## 客户端用法

```bash
# 方式一：令牌上设分组（推荐，一个专用令牌只走专线）
# 方式二：请求体带 group
curl -X POST https://api.example.com/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" \
  -d '{"model":"gpt-4o-mini","group":"accel","messages":[{"role":"user","content":"hi"}]}'
```

## 已知限制

- **并发计数是进程内的**：多实例部署时每个实例各算各的，实际并发上限是 N × limit。
  单实例（当前部署形态）准确。多实例需换成 Redis 计数。
- **缓存窗口**：订阅判定缓存 15 秒，套餐配置缓存 30 秒。开通/取消后接口会主动
  失效，但直接改库不会 —— 改库验证时记得重启或等窗口过去。
- **不做日额度**：用量已经由分组倍率按量扣费，再加一层日额度只会制造两套口径。

## 接口

用户端（`selfRoute`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/user/accel` | 套餐列表 + 我的订阅 + 付费余额 |
| POST | `/api/user/accel/subscribe` | 开通（`{plan_id}`） |
| POST | `/api/user/accel/auto_renew` | 开关自动续费（`{auto_renew}`） |

管理端（`adminRoute`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/user/accel/plans` | 全部套餐（含停用） |
| POST | `/api/user/accel/plans` | 新建 |
| PUT | `/api/user/accel/plans/:id` | 修改 |
| DELETE | `/api/user/accel/plans/:id` | 删除（存量订阅继续有效） |
| GET | `/api/user/accel/subscriptions` | 订阅列表（含用户名） |

## 验证

- 单元测试：`go test ./service/ -run TestAccel`（订阅状态、并发槽位、分组护栏）
- 真机探针 `hc48-probe.py`：两个本地假上游分别代表专线与普通出口，
  断言「未订阅 403 → 开通扣费 → 加速分组走到 18090 → 普通分组走到 18091 →
  并发上限 429 → 到期 403」
